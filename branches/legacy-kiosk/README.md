# LEGO scales: восстановление действующего киоска

Отдельная ветка проекта. В ней сохранён исходный киоск и восстановлена его логика с внешней настройкой BLE-адреса весов.

## Что лежит в папке

- `vesLego1.exe` — исходный EXE, полученный от пользователя, без изменений.
- `vesLego1.exe_extracted/` — извлечённые ресурсы и модули PyInstaller.
- `analysis/vesLego.dis.txt` — дизассемблированный Python-модуль из исходного EXE.
- `analysis/feasibility.md` — заметки о ключе BLE и сохранении адреса.
- `app/vesLego.py` — восстановленный киоск с теми же графикой, размерами сцены, шрифтами, анимациями, переходами и расчётом LEGO-деталей.
- `app/scale_setup.py` — отдельное окно поиска, проверки показаний и сохранения привязки.
- `app/data/` — извлечённые изображения и шрифт из исходного приложения.
- `build.ps1` — сборка двух автономных EXE.

## Запуск из исходников

Установите Python 3.11 x64. В PowerShell из `branches/legacy-kiosk` установите зависимости один раз:

```powershell
py -3.11 -m pip install -r requirements-build.txt
```

Затем настройщик и киоск можно запускать без сборки:

```powershell
py -3.11 app/scale_setup.py
py -3.11 app/vesLego.py
```

Сначала запустите настройщик, сохраните адрес весов, затем откройте киоск. Настройки для исходников сохраняются в `app/config.json`; собранные приложения используют `config.json` рядом с EXE.

Чтобы собрать EXE в отдельный каталог и не перезаписывать используемую сборку:

```powershell
.\build.ps1 -OutputDirectory dist-release
```

Киоск запрашивает полноэкранный размер текущего дисплея, затем берёт фактические размеры созданной поверхности Pygame и по ним масштабирует сцену. Фон подгоняется один раз при запуске; обработчик BLE и анимационный цикл не добавляют новых операций масштабирования для фона.

SHA-256 исходного EXE: `E01EC1A6AEEF9C02EDF7CD93BC5DFF5D78DB7B6FBA761373B5A005FF6562FE43`.

## Сборка

Нужен Python 3.11 x64. В PowerShell из этой папки выполните:

```powershell
python -m pip install -r requirements-build.txt
.\build.ps1
```

Сборка появится в `dist/`:

- `ScaleSetup.exe` — настройщик весов.
- `LegoScaleKiosk.exe` — киоск.

Держите оба EXE в одной папке. Перед первым запуском киоска откройте `ScaleSetup.exe`, выберите весы и нажмите «Сохранить выбор». Настройщик создаёт рядом `config.json`, например:

```json
{
  "address": "AA:BB:CC:DD:EE:FF",
  "rotated": false
}
```

Настройщик сохраняет выбранный BLE-адрес и остальные параметры конфига. В новом EXE старый MAC не зашит: без корректного `address` киоск не подключается к весам. Киоск читает адрес при запуске; после перепривязки закройте и запустите киоск заново. Пара адреса сохраняется на диске, поэтому перезагрузка ноутбука не требует новой привязки.

В киоске `Esc` закрывает приложение, `Ctrl+M` сворачивает его, `1` поворачивает сцену на 90°.

## Совместимость весов

Сканер по умолчанию показывает BLE-рекламу со службой весов `181D`, службой состава тела Xiaomi `181B` и именами, похожими на Mi Scale. Остальные устройства можно открыть кнопкой «Показать все». Если весы не распознаны в рекламе, откройте все устройства и нажмите «Проверить неизвестные»: настройщик последовательно подключится к ним и найдёт те, где доступна GATT-характеристика `2A9D`. Для подключения используется уже найденная BLE-запись без повторного сканирования; на подключение и перечисление GATT-сервисов отводится до 30 секунд на устройство. Поэтому проверка большого списка может занять несколько минут. Перед ней закройте киоск и другие программы, подключённые к весам. Для XMTZC04HM обычно используется `181D` / GATT-характеристика `2A9D`, которую читает этот киоск. Устройства с `181B` могут использовать другой формат GATT и перед сохранением нужно проверить кнопкой «Подключить и проверить».

Восстановленный обработчик киоска повторяет исходный формат `2A9D`: три байта или больше, вес в байтах `data[1:3]` little-endian, делённый на 200. Поддерживаются другие BLE-адреса без изменения EXE. Если реклама весов не содержит UUID или узнаваемого имени, используйте «Показать все», затем выберите устройство и проверьте, доступна ли характеристика `2A9D`.

## Текущий статус

Исходный EXE не заменяется и сохранён как резервный вариант. Новый киоск восстановлен по bytecode и тем же ресурсам, а не изменён внутри оригинального бинарного файла. Внешнее подключение настоящих весов и идентичность изображения в реальном запуске ещё нужно сверить на выставочном ноутбуке; до такой проверки эта сборка считается первой восстановленной версией.
