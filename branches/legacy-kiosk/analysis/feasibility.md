# Анализ `vesLego1.exe`

## Вывод

Нельзя сохранить EXE полностью неизменным и подключить к нему только внешнюю программу настройки: текущий EXE не читает адрес весов из конфигурации. Можно сохранить исходный файл как резервную копию и собрать отдельную совместимую версию основного приложения, внеся минимальное изменение: брать адрес из `config.json`. Отдельная программа настройки будет находить весы и записывать выбранный адрес в тот же файл.

Точное совпадение поведения и изображения достижимо как цель восстановления, но «100%» подтвердится только после сравнения новой сборки с оригиналом на том же ноутбуке и весах. Бинарный файл новой сборки не будет побайтно идентичен исходному.

## Что установлено статически

- Это 64-битное Windows-приложение, упакованное PyInstaller; внутри найден Python 3.11, Pygame, Bleak и WinRT Bluetooth-модули.
- В архиве извлечены главный модуль `vesLego.pyc`, 107 записей CArchive, PYZ с 348 модулями, семь экранных изображений (`0.png`–`4.png`, `n.png`, `d.png`) и шрифт `LEGO.ttf`.
- Основной модуль дизассемблирован; его инструкции и константы сохранены в `vesLego.dis.txt`. Исходный `.py` в архиве отсутствует.
- Адрес весов задан в коде: `5C:64:F3:3E:92:DA`. Приложение подключается через BLE GATT к характеристике `00002a9d-0000-1000-8000-00805f9b34fb` (Weight Measurement), подписывается на уведомления и повторяет подключение при разрыве.
- Вес извлекается из байтов `data[1:3]` как little-endian и делится на 200. Основной экран работает через Pygame, масштабируется из базового размера 1366×768 и имеет состояния ожидания и результата.
- Встроенный `config.json` расположен рядом с EXE. Текущая загрузка и сохранение конфигурации обрабатывают только поле `rotated`; поле адреса не читается. Поэтому внешняя программа может создать файл, но неизменённый EXE продолжит использовать константу из кода.
- В восстановленной логике сейчас три массы кирпичиков (`2.3`, `5.6`, `8.4` г), а не четыре размера из новой WPF-версии. Для точного совпадения следует сохранить именно исходные расчёты и ресурсы.

## План совместимой версии

1. Оставить этот EXE и извлечённые ресурсы в ветке как неизменённый эталон.
2. Восстановить основной Python-модуль из байткода; сохранить Pygame-композицию, обработку BLE, расчёт количества и тайминги.
3. Изменить чтение конфигурации: добавить поле `address`, сохранив `rotated` и старый адрес как резервное значение.
4. Сделать отдельную программу настройки: BLE-поиск, выбор весов, проверка получения показаний и запись `address` в `config.json` рядом с EXE.
5. Собрать новый основной EXE и проверить его на исходных весах и экране, сравнивая последовательность состояний с оригиналом.

Исходный EXE не запускался в рамках этого анализа. Сведения получены из PE-заголовка, PyInstaller-архива, извлечённых ресурсов и Python bytecode.
